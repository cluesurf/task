# Gentoo (ebuild → Portage overlay)

Gentoo packages are source recipes, not binaries. The workflow is:
render the ebuild, drop it into a local overlay, and let Portage
resolve it.

## Render

```sh
./make.sh
```

Writes `dist/cluesurf-task-<version>.ebuild`.

## Setup (one-time)

Create an overlay repo on GitHub (e.g. `cluesurf/gentoo-overlay`),
clone it, and seed the layout:

```sh
git clone git@github.com:cluesurf/gentoo-overlay ~/cluesurf-overlay
cd ~/cluesurf-overlay
mkdir -p metadata profiles app-misc/cluesurf-task
echo 'cluesurf' > profiles/repo_name
echo 'masters = gentoo' > metadata/layout.conf
git add . && git commit -m "init overlay" && git push

export GENTOO_OVERLAY_DIR=~/cluesurf-overlay
export GENTOO_CATEGORY=app-misc       # optional, this is the default
```

`publish.sh` will run `ebuild <file> manifest` if the `ebuild` tool
is available locally. On non-Gentoo hosts, you can skip the manifest
step locally and let CI in the overlay repo regenerate it.

## Publish

```sh
GENTOO_OVERLAY_DIR=~/cluesurf-overlay \
./publish.sh
```

## Install (end user)

```sh
sudo eselect repository add cluesurf git https://github.com/cluesurf/gentoo-overlay
sudo emaint sync --repo cluesurf
sudo emerge app-misc/cluesurf-task
```

## What ships to the overlay

- The rendered `cluesurf-task-<version>.ebuild` and its
  `Manifest` (regenerated by `ebuild ... manifest`). Nothing else.

No `SRC_URI`, no source tarball — Portage resolves `RDEPEND` directly.

## Notes

- `RDEPEND` entries use Gentoo's fully-qualified `category/package`
  names (`media-video/ffmpeg`, `media-gfx/imagemagick`, ...). A few
  packages may need USE-flag tweaks in your overlay.
- No `SRC_URI` — metapackages own no files.
- If you don't maintain an overlay, the ebuild can also be shipped
  as a tarball and installed with `emerge` from a local
  `PORTDIR_OVERLAY`.
